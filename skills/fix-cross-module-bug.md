# Skill：定位和修复跨模块 Bug

## 什么时候使用

Bug 同时涉及多个系统，或者表面症状和真实原因可能不在同一层时使用。

典型例子：

- 2D / 3D 坐标偏移；
- 贴图与碰撞体不一致；
- 建筑预览与实际位置不一致；
- Save 后 Runtime 状态错位；
- UI 输入穿透；
- 网络状态只在 Client 出错。

## 修改前必须读取

- `AGENTS.md`
- 相关 Spec / ADR
- 症状涉及的全部数据边界

## 调查顺序

### 1. 先复现
记录：

- 操作步骤；
- 必现 / 偶现；
- 正常结果；
- 实际结果。

### 2. 找 Source of Truth
明确：

- 哪个坐标 / 状态是真源；
- 哪一层只是表现；
- 中间有哪些转换。

### 3. 沿数据流追踪
不要从症状文件直接猜。

按：

Source
-> Transform / Adapter
-> Runtime Consumer
-> Presentation

逐层检查。

### 4. 找第一次出现错误的位置
优先修第一次产生错误数据的边界，而不是在后面补 offset / magic number。

## 必须保持的约束

- 不用第二个补偿值掩盖第一个错误；
- 不为了修 Visual Bug 修改 Gameplay Truth；
- 不同时大规模重构无关系统。

## 验证

- 原始复现场景；
- 相邻功能；
- 不同分辨率 / Scale / Camera（如相关）；
- Save / Load（如相关）；
- Network Host / Client（如相关）。

## 完成时输出

必须说明：

1. Bug 的根因在哪一层；
2. 为什么症状出现在另一层；
3. 修改了什么；
4. 为什么没有采用补偿式修复；
5. 回归验证结果。

## 如果任务只要求定位

停止在：
- 根因文件；
- 关键函数；
- 数据流；
- 建议修改方向。

不要修改代码。
